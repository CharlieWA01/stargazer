# 2026-10-20: The board (Milestone 1, step 1)

## Goal
Write Stargazer's first real engine code: the board, using the hybrid
design (DESIGN.md section 1), able to load any position from FEN and print
it. No moves yet.

## What was done
- **`src/bitboard.rs`:** a set of squares packed into a 64-bit number
  (bit 0 = a1 … bit 63 = h8), with chess-named helpers (add a square, does
  it contain e4, how many, walk through the squares). This is the one file
  for bit tricks, as DESIGN.md asks.
- **`src/board.rs`:** squares (`e4`), colours, pieces, castling rights and
  `Position`. A position keeps 12 bitboards plus a 64-square array; only
  `put_piece` and `remove_piece` change them, and always both.
  `is_consistent()` checks the two agree, and tests call it after changes.
  A position is a plain copyable value, ready for copy-make.
- **FEN:** `from_fen` reads all six fields (the two move counters may be
  left off) and rejects bad input with a reason: wrong rank count, a rank
  that isn't 8 squares, an unknown letter, a pawn on rank 1 or 8, not
  exactly one king per side, bad side to move, castling, en passant square
  or counters. `to_fen` writes it back.
- **UCI:** `position startpos` and `position fen ...` now set the board;
  `d` prints a diagram and the FEN. `position ... moves ...` is refused
  with an `info string` until moves exist.
- **Browser build in CI:** the WebAssembly target is added to
  `rust-toolchain.toml`, and CI builds the library for it (decision in
  `DECISIONS.md`).

## Problems and fixes
- A test first put a knight on f7 in Kiwipete, which is occupied. The
  `debug_assert` in `put_piece` (no piece may land on an occupied square)
  caught it at once. Moved the test to an empty square (d4). Good evidence
  that the guard works.

## How it was verified
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and
  `cargo test` (20 tests) pass.
- Proved the consistency tests can fail: removing the line in `put_piece`
  that updates the per-colour bitboard made 3 tests fail; restored.
- `cargo build --lib --target wasm32-unknown-unknown` succeeds.
- Ran the release binary: `position fen <Kiwipete>` then `d` prints the
  diagram and the same FEN back.

## Impact
Stargazer can now hold and show any chess position. Next: knight, king and
pawn moves.
